### CI (`.github/workflows/`, badges in README)
Three workflows, each runs only when its own files change, so a red badge says which area broke:
`api.yml` (backend pytest on Python 3.12 + compose config + both Docker image builds), `web.yml` (vitest, lint,
build on Node 24), `flutter.yml` (analyze + test on Flutter 3.44.1).
Lessons learned: compose needs `--env-file .env.docker`; web tests need Node ≥ 22 (Node 20 lacks
`markAsUncloneable`); **`pytest` lives in `backend/requirements-dev.txt`, not `requirements.txt`**, so the API job
installs the runtime file plus just the `pytest==` pin; failing test steps write their failure lines into the run's
annotations (readable through the public API without logging in).

## What is left / open

**Needs a real device (cannot be verified here)**
- NFC: URI-first tag dispatch, the Android `NDEF_DISCOVERED` https filter launching the app from a locked phone,
  iPhone background tag reading, NTAG215 capacity with a real sealed blob. Build the APK once and check the merged
  manifest has the host (`flutter build apk --debug`).
- Edge headers: Caddy vs nginx precedence for `/e/*` (`curl -I https://<host>/e/x` on a live stack).

**Go-live items**
- Set `CLARION_PUBLIC_URL` (plain https origin; the app refuses to start otherwise).
- A deployment on another host: build the app with `-PclarionPublicHost=<host>`.
- SMS: set `SMS_PROVIDER=twilio` and the three `TWILIO_*` values. Without them alerts are retried ~100 min then dropped.
- Printed QR codes from before the change keep working in the app but not as web links — reissue cards as needed.

**Known gaps (decided or noted, not built)**
- With **no network and no app**, a stranger can read nothing from the card — by design (the tag is encrypted).
  Medications *do* stay on the encrypted offline tag (so a responder account that fetched tag keys can read them offline).
- `Patient.phone` is unverified (that is why the SMS is always sent). OTP-verifying phones would let the in-app alert
  stand alone.
- No separate paramedic tier (needs a `User.responder_tier`); guardians of minors are not notified of card scans;
  audit rows during "acting" don't carry an explicit guardian marker (except consent); orphaned provisional
  profiles are never cleaned up; the 10-profile cap isn't race-proof.
- Per-IP rate limit (10/min) on the public routes: one noisy NAT can lock bystanders out of the page. Consider a
  higher public limit plus per-reference limits.
- Flutter: public tier shows a blank name (no "basic information only" label); Senior Mode shows the link-removed
  notice only on the next screen load.
- GitHub Actions warns that `actions/checkout@v4`, `setup-node@v4`, `setup-python@v5` run on the deprecated Node 20
  runtime — bump to the current majors when convenient.

   If a Linux-only failure appears, WSL2 is already enabled on this PC (an `Ubuntu` distro exists, stopped): start it,

## How to run things on this machine
- **Backend tests:** `cd clarion_clean/backend` then
  `SECRET_KEY=x OTP_HMAC_KEY=y <path>/medibridge_package/backend/venv/Scripts/python.exe -m pytest tests -q`
  (full suite ≈ 13 min locally — prefer letting GitHub run it).
- **Web:** `cd clarion_clean/web` → `npx vitest run`, `npm run lint`, `npm run build`
  (`node_modules` there is a junction to `medibridge_package/web/node_modules`).
- **Flutter:** the SDK is in `D:\New folder\flutter` (space in the path breaks `flutter test`). Map a space-free
  drive once per Windows session — PowerShell `subst X: 'D:\New folder'` — then
  `export PATH="/x/flutter/bin:$PATH"` and run `flutter analyze --no-pub` / `flutter test --no-pub` from
  `clarion_clean/mobile_flutter` (`pub get` fails here without Developer Mode; the generated `.dart_tool` was copied
  from `medibridge_package/mobile_flutter`). `subst` does not survive a reboot.
- **CI results without logging in:** the README badges show pass/fail per area. For the failing test names, the run
  page `https://github.com/lkaixian/clarion/actions/runs/<run id>` contains our "pytest failures" / "vitest failures"
  annotations (the test steps write them). The JSON API also works but only allows 60 requests an hour without a
  token — don't poll it. Full raw logs need a GitHub login.
- **Commits:** end messages with the `Co-Authored-By: Claude …` line; never add session links. Commit with explicit
  paths. Pushes to `main` are fast-forward from `clarion_clean` (`git push github main:main`; the remote is named
  `github`).
