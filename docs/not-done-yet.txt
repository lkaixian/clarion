CLARION - WHAT IS NOT DONE YET
Written 2026-10-10, after commits e7a796a and fd76914.
"Untested" means I wrote or configured it but never ran it for real.

==============================================================
1. CLOUDFLARE TUNNEL / PUBLIC SITE
==============================================================
- Origin TLS is still unverified. The public hostname works, but "No TLS Verify" is
  on. To turn verification on: in the dashboard set CA Pool to
  /etc/cloudflared/caddy-root.crt, keep Origin Server Name = clarion.larmkx.com,
  switch No TLS Verify off. The cert is mounted already. UNTESTED (the dashboard may
  not offer a CA Pool field). If caddy_data is ever deleted, copy the new root.crt out
  again: docker cp clarion-pi-proxy-1:/data/caddy/pki/authorities/local/root.crt proxy/certs/caddy-root.crt
- Cloudflare Access (login gate in front of the site) is NOT set up. Right now anyone
  with the URL can reach the login page.
- Spoofed X-Forwarded-For through the real tunnel was never tested (the rate limiter
  should ignore it; checked by reading code only).
- HSTS is max-age=300 (short on purpose). Raise it only when the domain is final.
- The seeded temporary passwords were pasted into a chat session. Sign in as each
  account once (you are forced to change it) so those passwords stop working.

==============================================================
2. RASPBERRY PI
==============================================================
- The stack has only run on x86 Docker Desktop (Windows). Never built or run on the
  Pi (ARM64). Whether every Python package builds on ARM64 is unknown. Expect a slow
  first build (10-20 min). Use a 64-bit OS.
- No backup for the Pi stack. Data is SQLite plus files on Docker volumes
  (clarion_db). The backup/restore service exists only in the main compose file.
- Local AI is switched off on this node (no Ollama). AI features use fallbacks.
- Local testing used a scratchpad override (port 9443), which is not in the repo.
